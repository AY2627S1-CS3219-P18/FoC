# Supplier Service: current response messages

This is an inventory of code paths, not a proposed response contract. Text in braces denotes a value inserted by the code. Successful routes return resource data or deletion results rather than a standard message. Unexpected errors produce the generic 500 below; unknown authenticated routes use Express's default 404 response rather than this envelope. Malformed JSON can also reach the generic error handler.

## Shared middleware

| Status | Route / condition | `message` | `details` |
| --- | --- | --- | --- |
| 401 | All `/api/v1` routes; missing or invalid token | `Bearer token is missing or invalid.` | absent |
| 403 | Supplier reads or admin routes; role not permitted | `You do not have permission to perform this operation.` | absent |
| 429 | Rate limit | `Rate limit exceeded. Try again later.` | absent; `Retry-After` header set |
| 500 | Unhandled errors | `Internal server error` | absent |
| 400 | POST admin suppliers; missing or invalid idempotency key | `A valid Idempotency-Key header (UUID) is required.` | header `Idempotency-Key`: `Send a UUID in the Idempotency-Key header.` |
| 400 | POST/PUT admin suppliers; malformed multipart | `The multipart/form-data request is malformed.` | absent |
| 409 | POST admin suppliers; key currently processing | `A request with this Idempotency-Key is still being processed.` | absent |

Sources: [authenticate](../src/middleware/authenticate.ts), [requireRole](../src/middleware/requireRole.ts), [rateLimit](../src/middleware/rateLimit.ts), [errorHandler](../src/middleware/errorHandler.ts), [requireIdempotencyKey](../src/middleware/requireIdempotencyKey.ts), [uploadPhotos](../src/middleware/uploadPhotos.ts), [admin controller](../src/controllers/adminSupplier.controller.ts).

## Reads and lookup management

| Status | Route / condition | `message` / details |
| --- | --- | --- |
| 422 | Supplier/admin list queries, supplier/admin detail IDs, reference management IDs and bodies | `One or more request values failed validation.`; `details` contains each Zod issue's field, location and message. ## Supplier create and update

For POST `/api/v1/admin/suppliers` and PUT `/api/v1/admin/suppliers/:id`, the top-level 422 message is `One or more supplier fields failed validation.` for Zod schema errors; `details` contains each issue. Some explicit validation failures use the same text for both `message` and the single body-field detail:

- `Supplier name is required.`; `Supplier name must not be empty.`; `Type must be Store or Facility.`
- `Location is required.`; `Location must be a number.`; `Location must be a positive id.`
- `version is required.`; `version must be a non-negative integer.`
- `is24h must be true or false.`; `isActive must be true or false.`; `isPhotoDirty must be true or false.`
- `category_id must be a list of category ids.`
- `Time must be HH:MM.`
- `A 24/7 Store must send a single entry {"day": 8, "open": "00:00", "close": "23:59"}.`
- `Operating hours are required for a Store.`
- `Day 8 is reserved for 24/7 suppliers; set is24h instead.`
- `A 24-hour schedule must be entered as 00:00–23:59.`
- `Each day may appear only once.`
- `photo_ids must be a list of photo ids and placeholder ids.`
- `placeholder_ids must be a list of strings.`; `placeholder_ids must be unique.`
- `photo_ids is required when isPhotoDirty is true.`
- `At least one field to update is required.`
- `The selected location does not exist.`
- `Unknown category id(s): {ids}.`
- `A supplier with the same name, type and location already exists.`
- `Photos were uploaded but isPhotoDirty is not true.`

For malformed JSON in `category_id`, `openingHours`, `photo_ids`, or `placeholder_ids`, status 400 returns `{field} must be valid JSON.` as both top-level message and body-field detail. Zod also supplies default issue messages for constraints without custom wording; these depend on the failed constraint. See [create validation](../src/validation/supplierInput.ts) and [update validation](../src/validation/supplierUpdateInput.ts).

Photo handling returns 422, repeating the message in `details` for `photos` or `photo_ids`:

- `Photos must be sent in the photos field.`; `Photos must be JPEG or PNG.`
- `Each photo must be at most 5 MB.`; `At most 10 photos are allowed.`; `Photos could not be accepted.`
- `placeholder_ids must match the number of uploaded photos.`
- `photo_ids must not repeat an id.`
- `Photo {id} does not belong to this supplier.`
- `Placeholder {id} is not listed in placeholder_ids.`
- `Every placeholder in placeholder_ids must appear in photo_ids.`
